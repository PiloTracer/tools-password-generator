# Web surface — API and UI contract SPEC

Pins the behaviour of the public web surface (`POST /api/generate`, `GET /api/health`, `GET /api/ready`) so hardening and future features can never silently change what a browser or a monitor observes.

**Status:** In review — 2026-10-25
**Needs:** nothing — this closes certify blocker **B1**.

---

## 1. Purpose

`/api/generate` is the only expensive, unauthenticated, internet-reachable endpoint in the product. It forks a Python interpreter per request. Until this SPEC it had **no written contract and no automated tests** (`R13`), which is exactly where abuse regressions hide.

This document is the *what*; the abuse analysis is the [threat model](../../standards/20261025-threat-model.md) (T1–T5, T18).

## 2. Scope

**In scope:** request validation, refusal behaviour, response shape, rate limiting, concurrency, readiness semantics.

**Out of scope:** the generation algorithm itself (owned by `password_generator.py` and [ADR 001](../../decisions/20261025-001-backend-stack.md)), and the Secrets Manager wire contract ([its own SPEC](../secrets-manager/20261025-SPEC.md)).

## 3. Endpoints

| Endpoint | Method | Auth | Purpose |
|---|---|---|---|
| `/api/generate` | POST | none (public) | Produce one password or passphrase |
| `/api/health` | GET | none | Liveness + dependency detail |
| `/api/ready` | GET | none | Can this instance generate? |

## 4. Request rules

| ID | Rule | Evidence |
|---|---|---|
| R1 | The request must be `POST` with `Content-Type: application/json`. Any other content type → **403** with `{"error": "Requests must use the application/json content type."}` | `route.ts:12-45`, `:160-163` |
| R2 | A cross-site caller is refused **403**: `Sec-Fetch-Site` must be `same-origin`, `none`, or absent; when `Origin` is present its host must equal the request `Host`. | `route.ts:26-45` |
| R3 | The body is capped at **16 KiB**. Exceeding `Content-Length` → 413 before reading; exceeding the actual body → 413 after reading. Never truncated, never half-parsed. | `route.ts:15`, `:166-180` |
| R4 | A body that is not a JSON **object** → 400 `{"error":"Invalid JSON body."}`. | `route.ts:171-178` |
| R5 | Rate limiting runs **before** the body is read, keyed on `generate:<client-ip>`. Over the limit → **429** with `Retry-After`. | `route.ts:148-159` |
| R6 | The client IP is taken from `X-Real-IP` first (nginx-owned), else the **last** `X-Forwarded-For` hop, else `"unknown"`. The first XFF hop is never trusted. | `route.ts:111-133` |
| R7 | `requestsPerMinute` semantics: **absent / empty / non-numeric / negative / below 1 → the built-in default of 30**; exactly `0` → throttling disabled (documented switch, owner-confirmed); otherwise the whole number capped at 6000. A missing value is never treated as unlimited. | `rate-limit.ts` `DEFAULT_REQUESTS_PER_MINUTE`, `normalizeLimit`, `coerceRequestsPerMinute`; `runtime-config.ts:114` |
| R7a | The default (30) is below the edge limit (20 r/m + burst 10) so a degraded policy layer tightens rather than loosens abuse limits. Verified end-to-end: with the Secrets Manager stopped, 30 requests returned 200 and the 31st returned 429. | `test/rate-limit.test.ts`; manual probe 2026-10-25 |
| R8 | When the limiter's key table is full, new keys are **refused**; existing counters are never discarded. | `rate-limit.ts:57-73` |
| R9 | At most **8** generator processes run concurrently (`GENERATOR_MAX_CONCURRENCY`); beyond that the request is refused immediately with **503** + `Retry-After: 2`, never queued. | `concurrency.ts`, `route.ts:296-303` |
| R10 | Mode defaults to `characters`; only the literal `"words"` selects passphrases. A mode disabled by policy → **403**. | `route.ts:185-190` |
| R11 | Numeric inputs are clamped to the policy range, never rejected for being out of range; non-numeric values fall back to defaults. | `route.ts:23-50` |
| R12 | `wordSeparator` is sanitised to `/^[\w\-_.:\|~]{0,5}$/`, must not start with `-`, and falls back to `-` when invalid. | `route.ts:82-101` |
| R13 | Passphrase generation with integrity enforcement on verifies the word-list digest first; a mismatch under `enforce` → **503**, a mismatch under `warn` logs and continues. | `route.ts:255-275` |
| R14 | A generated value is rejected (500) if it is non-printable ASCII or its length differs from the requested length. | `route.ts:305-325` |

## 5. Response shape

| Status | Body |
|---|---|
| 200 | `{"password": string, "meta": {"mode", "length", "source", "requestId"}}` |
| 400/403/413/429/503 | `{"error": string}` |

| ID | Rule | Evidence |
|---|---|---|
| R15 | Every response carries `Cache-Control: no-store, max-age=0`, `X-Content-Type-Options: nosniff`, and `X-Request-Id`. | `route.ts:136-146` |
| R16 | `meta.source` is `secretsmanager` when policy was loaded from the service, `defaults` when it fell back — the operator's only in-band signal of degradation. | `route.ts` respond block; `health.ts` |

## 6. Readiness semantics

| ID | Rule | Evidence |
|---|---|---|
| R17 | `GET /api/ready` returns **200** whenever this instance can generate, and **503** only for a broken generator or an unenforced integrity policy. | `health.ts:74`, `ready/route.ts:29` |
| R18 | A degraded Secrets Manager is reported (`status: "degraded"`, `checks.secretsManager`) but must **not** withdraw the instance — generation works from defaults. Owner decision 2026-10-25. | `health.ts:59-74` |
| R19 | `GET /api/health` always returns 200 when the process is up, with the dependency detail used by `./bin/start.sh health`. | `health/route.ts` |

## 7. Invariants

| ID | Invariant | Why |
|---|---|---|
| **I1** | A generated password is never logged, persisted, or sent to any third party. | The product's core promise (doc 01 §4). |
| **I2** | Refusal paths never invoke the generator. | Abuse control must cost no CPU. |
| **I3** | The API never re-implements generation; it validates and executes `password_generator.py`. | ADR 001. |
| **I4** | No response body ever contains a stack trace, absolute path, or secret identifier. | Reconnaissance resistance (T13). |
