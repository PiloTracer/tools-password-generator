# Secure Password Generator — Adjacency and deferred lanes (doc 03)

**What this is:** the lanes a user of this toolchain will plausibly want next, how they would attach to the existing contexts, and what is deliberately deferred out of v1.
**Status:** Approved — 2026-10-25
**Needs:** nothing — this is a seam map, not a commitment.

**Brownfield synthesis 2026-10-25:** inferred from the product shape and the owner's stated goals. Labelled **Inference** where no code or statement supports it.

---

## 1. Why this document exists

The fastest way to damage this product is to bolt a vault onto a generator. This document names the seams so that future requests attach at the right boundary — or are refused explicitly — instead of reshaping BC-GEN or BC-SM by accident.

## 2. Adjacent lanes

| Lane | Seam | Effort | Verdict |
|---|---|---|---|
| **Operator credential console** | BC-OPS → BC-SM admin listener | small | **natural next step** — the CLI rotation (ADR 005) is the first slice |
| **Secret versioning / rollback UI** | BC-SM versions + stages already exist | medium | plausible; contract supports it today, no new service needed |
| **Scheduled backup + off-host encrypted copy** | BC-OPS | medium | high value: closes `APP-06` (backups currently contain the master key) |
| **Metrics/alerting export** | BC-WEB + BC-SM logs | small-medium | high value; currently only JSON logs, no metrics (`APP-11` is unobservable today) |
| **Word-list management** | BC-GEN + integrity digest in BC-SM | small | plausible; today a word-list change requires re-seeding the digest |
| **Multi-user accounts / sharing** | new context | large | **refused for v1** — turns a single-operator tool into a multi-tenant product |
| **Password storage / vault** | new context | large | **refused** — contradicts the product's core promise that nothing is persisted |
| **Breach/HIBP checking** | outbound network | medium | **refused for v1** — leaks candidate passwords to a third party |
| **Mobile app** | new surface | large | out of scope; the UI is a thin surface over one API |
| **Multi-instance / HA Secrets Manager** | BC-SM store | large | blocked by the single-writer store (ADR 004); would need a real backend first |

## 3. Seams that must not be crossed

| Rule | Why |
|---|---|
| Adjacent features must not import BC-GEN internals | The single generator is the audit story (ADR 001) |
| No feature may persist a generated password | Core promise; violates doc 01 §4 |
| New privileged operations attach to the loopback admin listener, never the public edge | ADR 003 / contract BC9 |
| Any wire-contract addition needs a SPEC amendment + contract test before code | The contract suite is the compatibility guarantee |
