# Personas and UX direction v1

**What this is:** who uses the interface, the journeys that must not break, and the accessibility/state obligations the UI is held to.
**Status:** In review — 2026-10-25
**Needs:** an accessibility audit before any WCAG claim is made (see §5).

---

## 1. Personas

| # | Persona | Context | Goal | Frustration today |
|---|---|---|---|---|
| **P1** | **Operator** (solo, technical) | SSH on a VPS, occasionally on a laptop | Rotate credentials and restore from backup without downtime | Every step is a CLI flag; no confirmation of what actually changed |
| **P2** | **End user** (browser) | Copied a link, needs a password right now | One strong value, one click, gone | Unclear whether the value was saved anywhere; no visible entropy/strength signal on first paint |
| **P3** | **Integrating engineer** | Writes an AWS SDK call in another service | A scoped credential and a stable endpoint | Must discover that credential creation is on-box only |

Primary persona is **P2** for the UI and **P1** for everything else. P3 is served by the client guide, not the UI.

## 2. Journeys

| ID | Journey | Steps | Success |
|---|---|---|---|
| **J1** | Generate a password (P2) | Land → choose mode → set options → generate → copy | Strong value in < 2 s, no account, no trace |
| **J2** | Generate a passphrase (P2) | Switch to words → pick count/separator → generate | Memorable phrase, readable separator behaviour |
| **J3** | Rotate a credential (P1) | CLI mint successor → deploy → revoke predecessor | Zero downtime for the client |
| **J4** | Recover from a bad deploy (P1) | `rollback --list` → `rollback <stamp>` | Stack healthy on the previous images, data untouched |
| **J5** | Onboard a client (P3) | Read guide → on-box mint → configure SDK | First `GetSecretValue` succeeds |

## 3. UX direction

- **One screen, one primary action.** The generator is the page; no navigation, no account chrome. Power options stay visible but secondary.
- **Show the work.** Every generated value displays its mode and length so the user can trust what they got.
- **Never imply persistence.** Copy is ephemeral; the UI must not suggest the password is stored ("history" is in-page only).
- **Refusals are informative.** A 429/503/403 surfaces a human sentence and a retry hint, never a bare code.
- **Consistency over cleverness.** Same wording for the same condition on every surface (UI, `/api/*`, CLI).

## 4. State obligations

| State | Where | Obligation | Status |
|---|---|---|---|
| Loading | generate button | Disabled + in-flight indicator; no double submit | **present** (`framer-motion` transitions) |
| Success | result panel | Value + copy affordance + mode/length | **present** |
| Error | result panel | Human message, retry hint on 429/503 | **present** (message mapped from `error`) |
| Empty | result panel | Never shows a stale value from a previous session | **verify** |
| Rate-limited | result panel | Explain the wait; honour `Retry-After` | **partial** — message shown, no countdown |
| Degraded policy | page | `meta.source: "defaults"` is not surfaced to the user | **gap** — deliberate (operator signal, not user signal) |

## 5. Accessibility targets

| Target | Level | Status |
|---|---|---|
| Keyboard operable end-to-end (tab, enter, space) | required | **Unverified** — no audit run |
| Visible focus indicator on every control | required | **Unverified** |
| Every control has an accessible name | required | **satisfied in code** — the theme toggle has `aria-label`; form controls are wrapped in `<label>` elements (implicit association) |
| Colour contrast ≥ 4.5:1 for body text in both themes | required | **Unverified** |
| `prefers-reduced-motion` respected | required | **implemented 2026-10-25** — `<MotionConfig reducedMotion="user">` in `components/MotionProvider.tsx` |
| Result announced to assistive tech after generation | required | **implemented 2026-10-25** — `role="status" aria-live="polite"` announces the event and length, never the secret; errors use `role="alert"` |
| Responsive from 360 px to desktop | required | **partial** — Tailwind breakpoints present, not verified at 360 px |

**Claim discipline:** two mechanical gaps were closed on 2026-10-25 (reduced motion, live announcements). Contrast, focus visibility, 360 px layout and a full keyboard walkthrough still require an audit — nothing above may be called "accessible" until then. The honest statement is *"keyboard-first layout, labelled controls, reduced-motion support and live announcements present; visual/interaction audit outstanding."*

## 6. Cognitive load and consistency

- Three option groups at most (mode, strength, extras) — the current form respects this.
- Labels are verbs or nouns, never abbreviations: "Generate", "Length", "Words".
- Error text is a sentence, not a code path.
